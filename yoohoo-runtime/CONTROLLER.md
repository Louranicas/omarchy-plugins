# Explicit Yoohoo daemon and owner control

`yoohood serve DATA_ROOT CONTROL_ROOT` is a persistent controller entrypoint. Both absolute private directories must already exist and be distinct. It binds the owner-only control endpoint and prints its PID before reading one bounded, newline-terminated Startup JSON from a launcher-owned stdin pipe (3-second polling budget, 4096 bytes). The launcher can register that controller with the existing configured modal Host before supplying the Host identity. Startup fields match the prior fixture controller: modal_root, native_root, native_instance, host_pid/host_start_ticks, native_pid/native_start_ticks. No environment-based endpoint discovery, credentials, automatic instance fallback or installation is performed.

The owner can call `yoohood status|open|quit CONTROL_ROOT/modal.sock PID START_TICKS`. Each client pins the explicitly supplied controller identity; owner UID is the local control authorization boundary. Status is metadata-free. Open/Quit first observe the controller's random instance and revision, then submit that exact precondition once. A stale/replayed request or concurrent state change is refused; the CLI does not silently retry an action. Check status and explicitly act again after a refusal or lost reply. No keyboard bindings or service units are installed by these commands.

The closed protocol has version, optional instance, revision and operation (status/open/quit only). Unknown/duplicate fields and operations, partial or oversized frames are refused. One control connection at a time is accepted, with a 50ms absolute input deadline and bounded shared framing; a reply gets a separate 50ms deadline after bounded execution. The normal Quit client drops its connection after verifying the reply; the daemon waits for that EOF for at most250ms before exit to avoid invalidating its process identity mid-reply. This grace period is not an application-acknowledgment or delivery guarantee under failure.

Idle uses the reviewed bounded Sources policy, exposes Waiting/Ready, and never acquires a modal lease merely because attention arrives. Only Open in Ready consumes the source after fresh draining, binds the data endpoint and makes a new authenticated Client/acquire/Service::attach. Empty lists may open; readiness does not fabricate attention. Every open obtains fresh presenter/auth/registry state. Host executable/process continuity is retained from startup; a changed or lost Host makes this controller Faulted, not silently rediscovered.

Service now caches its first release result. A complete release reply is usable because the existing Host returns it only after Actor::dismiss verifies both presenter exit and compositor dismissal; the configured native backend owns actual child/readback proof. Closed alone is insufficient. Any service step error or unconfirmed/expired/lost release blocks hand-back. Drop never overwrites the first outcome with a second no-lease result. After confirmed clean close, into_sources consumes the old client/view/auth/data channel and clears selection, pending activation and queued effects. Only still-observed Native/Runtime/original clock state resumes as nonmodal Sources. Idle disconnect can then recover with new observation identities. No failed or uncertain native effect is retried.

Status cleanup_confirmed is false initially (no release receipt), false while active/uncertain and true only after a confirmed owned release. It is not a claim about other Host clients. Quit while active either obtains that confirmation and stops or reports Faulted/uncertain. Quit while idle stops without inventing a release proof. Faulted cannot Open or automatically construct a new Host/controller. SIGTERM/process kill is not a new graceful shutdown API in this slice; existing Host controller-death monitoring remains the fallback, without claiming an acknowledgment to the dead controller.

Tests use real source/control/data Unix IPC and the real Host actor/lease protocol with simulated presenter lifecycle and compositor readback. They cover explicit open, stale instance/revision/replay, malformed/partial frames, active-open refusal, clean hand-back, idle reconnect, new fences, old presenter refusal, uncertain focus and confirmed/refused active Quit. An actual spawned daemon plus CLI subprocesses exercise status→open→presenter Close→open→Quit, actual waits and socket removal. Dedicated test processes/threads retain cleanup custody on assertion paths; filesystem/kernel progress is not hard realtime.

This is executable controller wiring, not installed/native acceptance. Real GTK/Hyprland configured Host operation, desktop bindings, deployment and full historical CLI aliases remain separate qualification work. The older isolated controller-link and fixture/control entrypoints are preserved. No provider/network service is contacted.
