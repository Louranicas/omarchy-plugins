# Nonmodal source recovery (partial Y-014)

`reconnect::Sources` owns a read-only Native adapter and Runtime, never a modal Client, lease, target token, presenter or effect executor. It retains the originally discovered Endpoint and its pinned process/directory identity. A different compositor PID, executable or instance needs new trusted configuration; this component does not rediscover or silently follow another instance.

Construct it with the Runtime's original Instant clock origin and a validated Policy. Default policy is 100 ms exponential base delay, capped at 2 s, plus 0–50 ms jitter; 500 ms per attempt; eight consecutive failures. These are explicit initial policy choices, not performance results. Constructors constrain base delay, jitter, transport budget and consecutive failure count. A successful snapshot resets the consecutive failure count. Exhaustion is sticky for this object. No internal sleep, retry loop, background task or automatic recovery from exhaustion is provided.

Each `step` performs one source poll or at most one connection/snapshot attempt. Backoff is computed from attempt completion, not its start. Event connect, clients snapshot and active-window query share one absolute deadline; late completion is not Ready. Filesystem/kernel scheduling is not cancellable. A private schedule accepts injected time and entropy values for deterministic backoff tests; public steps use Instant and bounded nonblocking Linux getrandom. Failed entropy, clock regression or repeated/zero adjacent epoch fails closed. Source disconnect, malformed/partial events and snapshot races close the selection, discard pending activation/effects, retain stale metadata as unavailable, and drop the old event stream before retry. Each attempt gets a fresh random observation epoch; old pending attention identities cannot survive a successful resnapshot. No old urgency is inferred from a window's presence: subsequent trusted events create new attention.

`view` and `status` describe the last observed source state, not an authority grant or instantaneous liveness proof. `take_ready` explicitly transfers Native, Runtime and the original clock origin, after bounded event draining. It consumes the supervisor; on failure it drops the source. The caller must separately create a new authenticated modal Client, acquire a new lease/presenter and obtain fresh target tokens through existing Service::attach. This module cannot supply or reuse any of those objects. The fixture controller and installed startup are not automatically rewired by this slice. Existing service failure still closes that service; reconnect never resumes a failed/uncertain effect.

Tests exercise actual private Unix sockets for event EOF, fresh snapshot/attention identities, stale activation rejection, partial snapshot race, finite exhaustion, cumulative query deadline and renamed discovery-directory refusal. Deterministic unit tests cover exact retry timing/jitter/cap, invalid policies, clock regression and clearing a pending activation before retry. These are simulated compositor sources, not installed Hyprland recovery or a newly qualified end-to-end reacquisition workflow. Current modal tests remain separate; complete Y-014 and native/release gates remain open.

Independent review R1 found that an idle source poll could finish late and still qualify transfer. Both Native poll completion (including idle results) and the final take_ready transfer now recheck the caller's absolute deadline. Native uses the existing invalidation path to revoke identities, health and pending activation. A private completion-clock test injects the exact expiry instant without sleeping; the preserved independent delayed-poll reproduction remains separate historical evidence.
