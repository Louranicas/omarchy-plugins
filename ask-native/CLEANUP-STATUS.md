# Typed backend cleanup observation

Retain `let observer = handle.lifecycle.clone()` before consuming `handle.finish()` or dropping the handle. `observer.snapshot()` samples the actual retained ACP reap receipt; `View.lifecycle` is a published snapshot and can become stale. UI rendering, permission choices, adapter launch and the existing boolean finish result are unchanged.

`Status.phase` reuses the core Phase and is absent until a worker is observed. `terminal` records backend terminal/fatal detection or worker-thread completion. `stop_requested` records explicit Handle stop/drop, while core Closing stages describe provider shutdown. `thread_finished` is set only by a guard dropped after the Worker (including unwinding); it is not child-reap proof. Fatal adapter cleanup can complete while the backend thread and presenter remain alive.

Cleanup distinguishes `NotSpawned` (no spawn attempt), `Unverified` (spawn attempted but no receipt exposed), and `Child(ReapState)` using existing Running/Outstanding/Reaped/CustodyLost values without inventing a parallel child state machine. Worker::spawn can fail after child creation, so even an apparent launch error is conservatively Unverified. Reaped means the ACP direct-child receipt confirms wait completion. CustodyLost, signals, core Closed and thread_finished must not be substituted for this receipt. Outstanding can later become Reaped through the existing retained reaper; the Observer retains that live receipt after Handle completion.

The facts are observations of one backend, not authorization or an atomic snapshot of the whole desktop. No restart method, child relaunch, prompt replay, fresh modal acquisition or permission policy is added. A future controller must additionally revoke old UI actions, verify old presenter exit/compositor cleanup and acquire a fresh full fence before a separate explicitly authorized replacement. This module cannot certify those boundaries.

Tests exercise real fixture cancellation without falsely marking terminal, malformed adapter output followed by actual reaping, observer survival after finish, failed spawn without a receipt, and ECHILD by waiting exactly the transport-owned child before Transport::close. That last test changes no process-wide SIGCHLD policy and never waits for unrelated children. Poll budgets are checked between operations, not hard kernel scheduling bounds.
