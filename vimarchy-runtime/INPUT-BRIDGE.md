# Experimental matched-input bridge

`input_bridge` is a bounded single-device/single-hint receiver and state machine. It is not connected to a production compositor exporter or the managed service. Constructing it, authenticating a socket or supplying a valid frame does not prove physical input or acquire a modal lease.

The trusted controller supplies the existing full Session Context and Auth, a fresh nonzero random 128-bit bridge epoch, the admitted device/code and hint. Only a pinned compositor process may connect to the dedicated private `modal.sock`. Frames carry version, full Auth, bridge epoch, source revision, strictly consecutive sequence, source CLOCK_BOOTTIME milliseconds, exact device/code and one of Ready(held), Down, Up or Cancel. Unknown fields, duplicate fields, oversized frames, stale/future timestamps, wrong context or input lifetime, replay and gaps revoke the session. No reconnect into that session occurs.

Ready records the initial held baseline; releasing a preheld key produces only Tick, never a tap. The receiver assigns press IDs. A fresh Down followed by exact Up enters the existing Session reducer. A returned Batch is still only an intent: the caller must consume it and pass it through the existing authoritative Host checks. Error invalidates the Session; the lifecycle owner must release/dismiss through Host. No raw compositor command exists in this API.

Ingress probes live idle without fabricating releases. No connection yet or an idle established connection returns None. Readiness means data or EOF, not a complete frame; once reading starts the absolute caller deadline is capped at 40 ms. Partial-frame timeout, EOF and peer loss revoke. The controller must continue driving reducer Tick, lease expiry, compositor-state observation and Host continuity checks while idle.

The 40 ms source-age cutoff is a conservative fixture constraint, not a measured latency guarantee. Source and receiver must share kernel/time namespace. Tests separately exercise supplied logical times and actual CLOCK_BOOTTIME socket traffic; clock-origin mapping to the production controller and suspend continuity still require integrated qualification. Delayed events are backdated by their bounded age and rejected if they would regress Session time. This may refuse input under scheduling pressure; it never authorizes retry or extends a previous gesture from an acknowledgment.

The isolated native diagnostic separately establishes an owned SKeybind press/release pair, exact current-binding pointer and one-use raw/global correlation on the pinned Hyprland ABI. That evidence uses one synthetic virtual keyboard and counter outputs. It is not yet the producer of this socket protocol. Before joining them, preserve initial-held/device census admission, later cancellation, reentrancy, keymap/reload/death revocation, queue backpressure and teardown; reject direct dispatcher calls lacking that matched callback context. A hostile compositor or loaded plugin is outside the trust boundary. Same-UID control/injection is not human-input attestation.

Still unsupported: production action exporter and admission handshake, multi-device active routing, modifier/Alt capture, multiletter hints, radial/scratchpad routing, source/static-submap integration, physical device/IME/lock/inhibitor qualification and production native acceptance. The passive renderer and existing guarded effects remain unchanged.

Validation: `cargo test -p vimarchy-runtime`; `cargo clippy -p vimarchy-runtime --all-targets -- -D warnings`. No live service or desktop configuration is needed by the receiver tests.
